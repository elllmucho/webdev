01 · Selectors & Specificity

How CSS targets elements — and how conflicts get resolved

Basic Selector Types

The five ways to target elements before you add relationships or state

* Universal* { margin: 0; } — targets every element
E Type / Elementp { line-height: 1.6; } — targets every element of that tag
. Class.card { padding: 1rem; } — targets every element with that class
# ID#main-nav { ... } — targets the one element with that ID
, Groupingh1, h2, h3 { font-family: ...; } — applies one rule to several selectors

Combinators — Selecting by Relationship

Target an element based on its position relative to another

A B Descendant.card p { } — any B inside A, at any depth
A > B Child.card > p { } — B is a direct child of A
A + B Adjacent siblingh2 + p { } — B immediately after A
A ~ B General siblingh2 ~ p { } — any B after A, same parent

Attribute Selectors & Pseudo-Classes

Target elements by their attributes, or by the state they're currently in

Attribute selectors

Who Wins? The Specificity Hierarchy

When two rules target the same element, the browser scores each selector and the higher score wins

1000Inline style — style="color:red;"
100ID selector — #header { }
10Class / Attribute / Pseudo-class — .btn, [type], :hover
1Element / Pseudo-element — p, ::before

Worked example

#nav .item a:hover { color: orange; }
#nav1 ID  →  +100
.item1 class  →  +10
:hover1 pseudo-class  →  +10
a1 element  →  +1

Total specificity = 100 + 10 + 10 + 1 = 121

!important overrides normal specificity entirely — powerful, but makes styles hard to override later. Use sparingly.

02 · The Cascade

How the browser picks a winner when rules conflict

Order of Precedence When Rules Conflict

1Origin & Importance — user !important > author !important > author styles > user styles > browser default
2Specificity — higher specificity wins (inline > ID > class > element)
3Source Order — if specificity ties, the last rule declared wins

Inheritance & Special Values

Some properties pass down from parent to child automatically — others don't

Inherited by default

color, font-family, font-size, line-height, text-align, visibility

Not inherited by default

margin, padding, border, background, width, height

inheritForce this property to take its parent's computed value
initialReset the property to the CSS spec's default value
unsetActs as inherit if the property normally inherits, else initial
revertReset to the browser's built-in (user-agent) stylesheet value

03 · The Box Model

Every element is a box: content, padding, border, margin

Content → Padding → Border → Margin

Contentwidth / height — the actual text, image, etc.
PaddingSpace between content and the border
BorderThe line around the padding (width, style, color)
MarginSpace between this box and neighboring elements
Try it Yourself »
Result

box-sizing: content-box vs border-box

content-box (default)width: 300px applies to content only — rendered width = 300 + padding + border
border-box (recommended)width: 300px includes padding + border — rendered width stays 300px, padding/border eat into the content area instead
Try it Yourself »
Result

Sizing Units: px, %, em, rem

pxFixed pixel value — doesn't scale with user/browser settings. e.g. 16px
%Relative to the parent element's font-size. e.g. 150%
emRelative to the current element's (or parent's) font-size — compounds when nested. e.g. 1.5em
remRelative to the root (<html>) font-size — predictable, recommended for accessibility. e.g. 1.5rem

06 · Web Fonts

Going beyond web-safe fonts with @font-face and Google Fonts

@font-face & Google Fonts

Self-hosted with @font-face 
@font-face {
  font-family: "Poppins";
  src: url("poppins.woff2")
       format("woff2");
  font-weight: 400;
  font-display: swap;
}
Hosted via Google Fonts 
<link rel="stylesheet"
  href="https://fonts.googleapis.com/css2?family=Poppins&display=swap">
body { font-family: "Poppins", sans-serif; }
Try it »
Result
💡 font-display: swap shows a fallback font immediately, then swaps once the custom font loads — avoids invisible text while waiting.
